### Column mapping strategies (S3m)

| Strategy | Correct | Total time (3 sheets) | Columns flagged for review |
|---|---|---|---|
| Whole table in one prompt, raw | 15/19 | 17.7 s | — |
| Whole table + reconciliation with value-shape profile | **19/19** | 17.7 s | 4 |
| One prompt per column, raw | **19/19** | 34.3 s | 0 |
| One prompt per column + reconciliation | 19/19 | 34.3 s | 0 |

The raw whole-table errors were all on the messiest sheet (one free-text column): a "Who" column holding
name + hospital number read as `documented_by`, staff initials read as `ignore`, and a yes/no column left
unanswered. Lantern's deterministic profiler (`src/core/profile.ts`) recognised each from the values alone,
and the reconciliation (`src/core/mapping.ts`) corrected them while flagging them for the reviewer.

**Decision:** adaptive mapping — one whole-table prompt first (fast proposal), then per-column prompts only
for the columns where Gemini Nano and the value shapes disagree; anything still disputed goes to the reviewer.
