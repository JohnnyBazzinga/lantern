# Gate A — on-device feasibility (2026-11-21)

Run in the Lab (`#/lab`) on the developer's laptop, desktop Chrome with Gemini Nano, route `ONLY_ON_DEVICE`.
Data: synthetic development sheets in `public/fixtures/dev/` (3 improvised layouts × 10 rows, fictional patients),
scored against `dev-key.json`. This set is for tuning; the frozen benchmark is separate.

Hardware / browser: Chrome 158, Gemini Nano `available`, local context window 9,216 tokens; laptop with 16 GB RAM and an RTX 3060 (OS and driver: _to be filled in_).

### Column mapping strategies (S3m)

| Strategy | Correct | Total time (3 sheets) | Columns flagged for review |
|---|---|---|---|
| Whole table in one prompt, raw | 15/19 | 17.7 s | — |
| Whole table + reconciliation with value-shape profile | **19/19** | 17.7 s | 4 |
| One prompt per column, raw | **19/19** | 34.3 s | 0 |
| One prompt per column + reconciliation | 19/19 | 34.3 s | 0 |

The raw whole-table errors were all on the messiest sheet (one free-text column): a "Who" column holding
name + hospital number read as `documented_by`, staff initials read as `ignore`, and a yes/no column left
unanswered. Lantern's deterministic profiler (`src/core/profile.ts`) recognised each from the values alone,
and the reconciliation (`src/core/mapping.ts`) corrected them while flagging them for the reviewer.

**Decision:** adaptive mapping — one whole-table prompt first (fast proposal), then per-column prompts only
for the columns where Gemini Nano and the value shapes disagree; anything still disputed goes to the reviewer.

## Cloud on the free tier (2026-11-21)

AI Logic enforces App Check: a call without a token gets `401 Firebase App Check token is invalid`.
One tiny synthetic prompt per model from the hosted origin, Spark plan (Gemini Developer API free tier):

| Model | Result |
|---|---|
| `gemini-3.8-flash` | 500 "currently experiencing high demand", then 429 quota exceeded |
| `gemini-3.5-flash` (served as `gemini-3.6-flash`) | OK, 4.9–42.7 s |
| `gemini-3.6-flash` | OK, 68.0 s |
| `gemini-3.5-flash-lite` | **OK, 0.7–1.9 s** |
| `gemini-4-hydrogen` | 503 after 179 s |

**Decision:** `cloud_model = gemini-3.5-flash-lite`, `cloud_fallback_model = gemini-3.6-flash` (Remote Config
template v2). Cloud calls time out after 45 s, retry once on 429/5xx, skip straight to the fallback after a
timeout, and every failed attempt stays in the ledger. The model can be switched from the console without a new build.

| Method | Same-act recall | False merges | Corrections found | Open questions kept | Ready for re-entry (27) |
|---|---|---|---|---|---|
| Latest file only | 0/21 | 0 | 0/3 | 0/2 | 26 |
| Exact copies only | 12/21 | 0 | 0/3 | 2/2 | 36 |

Pair judgments: 8/11 full relations right as answered, 11/11 after Lantern's rules (the 3 corrections were

### Drill with Gemini Nano (S5, prompt `same-event` v2, developer laptop)

| Run | Pairs judged on device | "Same act?" right | Full relation, raw → after rules | Same-act recall | Ready (27) | Reconciliation |
|---|---|---|---|---|---|---|
| 1, no cloud | 10/11 | 9/10 | 6 → 10 | 20/21 | 28 | 381 s |
| 2, no cloud | 10/11 | 9/10 | 6 → 10 | 20/21 | 28 | 393 s |
| 3, + cloud second opinion | 11/11 | 10/11 | 7 → 11 | 21/21 | 27 | 37 s |

All runs: 0 false merges, 3/3 corrections, 2/2 open questions kept, 3/3 earlier-only rows kept, 4/4 identity
issues found. Nano's only systematic miss is calling a genuine repeat dose ("morphine 01:45", 3 h 15 after the
first) the same act; the time rule separates it every time. The cloud second opinion (7 calls) fixed 4 local
errors; its one wrong raw answer was overruled by the same rules.

**Stall:** in runs 1 and 2 a single on-device call (a different pair each time) ran for about 6 minutes and
returned nothing usable, which is where the extra ~345 s went; the same happened once in an earlier four-way
run (372 s). Consistent with constrained decoding looping inside the unbounded `evidence` string until the
9,216-token context is full. The unjudged pair is not lost: it goes to the reviewer as "possibly typed twice"
with no suggestion, which is why "ready" reads 28. **Fix (prompt v3 + runtime):** `evidence` limited to 12 words
in the prompt; every on-device call gets a 45 s deadline through Chrome's `AbortSignal`, and a stalled or
cut-off answer is retried once on a fresh session, all visible in the ledger.
